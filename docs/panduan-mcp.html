1. Apa itu MCP Infinity Konten

MCP (Model Context Protocol) adalah standar terbuka yang membuat asisten AI bisa memakai "tools" dari sistem lain. MCP Infinity Konten memberi asisten Anda 27 tools untuk mengurus website bimbelinfinity.com: menulis artikel blog, mengubah hero, FAQ, dan program, mengelola video testimoni dan data alumni, kontak dan media sosial, tema warna, serta SEO.

Cara kerjaAsisten memanggil tool → server MCP mengedit file data di repo GitHub website → build_site membangun ulang halaman → publish mengirim ke GitHub → Railway men-deploy ulang bimbelinfinity.com dalam 1–2 menit.
Dua cara aksesRemote (untuk Grok, Muse, ChatGPT, Claude.ai, bot lain): alamat HTTPS dengan token.
Lokal (Claude Code di komputer yang punya folder website): otomatis lewat .mcp.json.
Yang tidak bisaMengubah tata letak atau desain halaman, mengedit warna satu per satu (hanya memilih tema), menulis harga, dan menerbitkan tanpa persetujuan.
Aman untuk dicobaSemua perubahan tercatat sebagai commit di GitHub dan bisa dibatalkan (bab 13). Tool yang menghapus atau menerbitkan selalu butuh confirm: true.

Di mana MCP_TOKEN?

  1. Buka Railway → project website → service infinity-konten-mcp → tab Variables.
  2. Klik ikon mata di samping MCP_TOKEN, lalu salin.
  3. Tempel hanya di pengaturan asisten yang Anda percaya. Jangan kirim di chat grup, email, atau dokumen publik.
Token = kunci edit websiteSiapa pun yang memegang MCP_TOKEN bisa mengubah dan menerbitkan isi website. Kalau bocor: buat token baru (node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"), ganti nilai MCP_TOKEN di Railway, lalu Deploy. Semua koneksi lama otomatis tertolak. Perbarui token di setiap asisten.

Tes cepat dari terminal

curl -s https://mcp-infinity.up.railway.app/mcp \
  -H "Authorization: Bearer <MCP_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

Hasilnya daftar 27 tools. Kalau 401: token salah. Kalau tool baru tidak muncul: restart service di Railway (bab 12).

3. Menyambungkan Grok

Grok bisa memakai MCP remote lewat pengaturan konektor/tools di aplikasinya atau lewat xAI API. Nama menu dan nama field bisa berubah mengikuti versi xAI; prinsipnya selalu sama: alamat server + header Authorization.

Lewat aplikasi atau dashboard

  1. Buka pengaturan konektor / MCP / tools di Grok, pilih tambah server remote (Custom MCP).
  2. Isi nama infinity-konten dan URL https://mcp-infinity.up.railway.app/mcp.
  3. Kalau ada kolom header atau authorization: isi Bearer <MCP_TOKEN>. Kalau tidak ada: pakai URL https://mcp-infinity.up.railway.app/mcp/<MCP_TOKEN>.
  4. Tempel system prompt dari bab 7 ke instruksi kustom Grok.
  5. Tes dengan perintah: "Panggil site_overview dan ringkas isinya."

Lewat xAI API (untuk developer)

Contoh bentuk permintaan dengan tool MCP remote. Sesuaikan nama field dengan dokumentasi xAI terbaru.

{
  "model": "grok-4",
  "input": "Audit SEO website lalu laporkan 3 perbaikan terpenting.",
  "tools": [{
    "type": "mcp",
    "server_label": "infinity-konten",
    "server_url": "https://mcp-infinity.up.railway.app/mcp",
    "headers": { "Authorization": "Bearer <MCP_TOKEN>" }
  }]
}

4. Menyambungkan Muse

Muse dan asisten pribadi sejenis biasanya punya menu integrasi untuk "MCP server" atau "custom connector".

  1. Buka Settings → Integrations / Tools / MCP → Add MCP server (remote / HTTP).
  2. Isi URL https://mcp-infinity.up.railway.app/mcp, transport Streamable HTTP (bukan SSE, bukan stdio).
  3. Autentikasi: pilih "Bearer token" / "API key header" dan isi MCP_TOKEN. Kalau tidak ada pilihan header, pakai URL dengan token di ujungnya.
  4. Tambahkan system prompt dari bab 7 sebagai instruksi asisten.
  5. Tes: "Tampilkan daftar artikel blog." (tool list_posts).

Kalau aplikasi meminta format JSON konfigurasi, pakai bentuk umum berikut:

{
  "mcpServers": {
    "infinity-konten": {
      "type": "http",
      "url": "https://mcp-infinity.up.railway.app/mcp",
      "headers": { "Authorization": "Bearer <MCP_TOKEN>" }
    }
  }
}

6. Bot buatan sendiri (n8n, kode)

Server menerima JSON-RPC lewat POST. Tiga panggilan dasar: initialize, tools/list, tools/call. Di n8n atau Make, pakai node MCP Client (jika ada) dengan URL dan header di atas, atau node HTTP Request.

// Node.js 18+
const URL = "https://mcp-infinity.up.railway.app/mcp", TOKEN = process.env.MCP_TOKEN;
async function call(name, args = {}) {
  const r = await fetch(URL, {
    method: "POST",
    headers: { "Content-Type": "application/json", Authorization: "Bearer " + TOKEN },
    body: JSON.stringify({ jsonrpc: "2.0", id: Date.now(), method: "tools/call",
                           params: { name, arguments: args } }),
  });
  const j = await r.json();
  return j.result.content[0].text;   // isi balasan (JSON dalam bentuk teks)
}
console.log(await call("site_overview"));
console.log(await call("seo_audit"));
# Python
import os, requests
URL, TOKEN = "https://mcp-infinity.up.railway.app/mcp", os.environ["MCP_TOKEN"]
def call(name, args=None):
    r = requests.post(URL, headers={"Authorization": f"Bearer {TOKEN}"},
        json={"jsonrpc": "2.0", "id": 1, "method": "tools/call",
              "params": {"name": name, "arguments": args or {}}})
    return r.json()["result"]["content"][0]["text"]
print(call("list_posts"))

7. Instruksi untuk asisten (system prompt)

Tempel teks ini ke "custom instructions", "system prompt", atau "persona" di Grok, Muse, ChatGPT, atau asisten lain. Instruksi ini menjaga bot tetap jujur dan tidak menerbitkan tanpa izin.

Kamu adalah editor konten website Bimbel Infinity (https://bimbelinfinity.com), bimbel persiapan seleksi PKN STAN di Bintaro sejak 2013. Kamu bekerja lewat MCP "infinity-konten".

Aturan:
1. Mulai setiap sesi dengan site_overview.
2. Jangan pernah mengarang data: angka kelulusan, harga, jadwal, kuota, nilai ambang batas, nomor kontak, akun media sosial, koordinat, jam buka, atau kutipan siswa. Pakai hanya data dari pengguna atau dari situs. Untuk hal yang berubah tiap tahun, arahkan pembaca ke pengumuman resmi PKN STAN.
3. Tulis dalam bahasa Indonesia yang jelas untuk orang tua dan siswa. Kalimat pendek, tanpa jargon pemasaran.
4. Artikel blog: buka dengan "Jawaban singkat" 2-3 kalimat, subjudul berbentuk pertanyaan, minimal 300 kata, 2-4 FAQ, dan link ke artikel lain bila relevan.
5. Setelah mengedit: build_site, lalu seo_audit, lalu tunjukkan review_changes kepada pengguna.
6. publish, delete_post, dan remove_testimonial_video hanya setelah pengguna menyetujui secara eksplisit; kirim confirm: true hanya setelah itu.
7. Sekitar 2 menit setelah publish, jalankan ping_index.
8. Kalau tool menolak input, laporkan alasannya kepada pengguna; jangan memaksa dengan data karangan.

8. Alur kerja standar

site_overview→edit→build_site→seo_audit→review_changes→publish (confirm)→ping_index
  1. site_overview: lihat isi website, tema aktif, dan apakah ada perubahan yang belum terbit.
  2. Edit: pakai tool sesuai tugas (bab 9 dan 10).
  3. build_site: bangun ulang semua halaman, sitemap, dan llms.txt; mengecek link rusak.
  4. seo_audit: skor 0–100 dan daftar perbaikan; perbaiki yang bisa diperbaiki.
  5. review_changes: daftar file yang berubah. Tunjukkan ke pengguna.
  6. publish dengan confirm: true setelah pengguna setuju: commit dan push ke GitHub; website tayang 1–2 menit kemudian.
  7. ping_index sekitar 2 menit setelah publish: memberi tahu Bing/Copilot dan mesin pencari lain.

11. Aturan dan pengaman

  • Konfirmasi wajib: publish, delete_post, remove_testimonial_video ditolak tanpa confirm: true.
  • Tanpa harga: update_program menolak teks yang berisi harga; biaya dijelaskan konsultan.
  • Kontak tervalidasi: nomor WhatsApp otomatis dirapikan ke format 62…; email, telepon, dan nama akun sosmed dicek formatnya per platform.
  • Lokasi tervalidasi: koordinat harus di wilayah Indonesia, jam buka format HH:MM, kode pos 5 angka.
  • Tema terkunci: hanya bisa memilih tema yang sudah disiapkan (hijau, biru); build menolak tema yang gagal cek kontras WCAG AA.
  • Video: hanya dari akun Cloudinary jnye0bk5; file asli tidak diubah.
  • Publish batal kalau ada link rusak.
  • Kejujuran data: asisten diminta (bab 7) tidak mengarang angka, jadwal, kuota, kutipan, kontak, atau lokasi. Periksa setiap artikel yang memuat angka sebelum menyetujui publish.

12. Mengatasi masalah

GejalaPenyebab dan solusi
401 unauthorizedToken salah atau sudah diganti. Salin ulang MCP_TOKEN dari Railway.
502 / Application failed to respondService MCP mati atau target port domain tidak cocok. Cek Deploy Logs di Railway; samakan port domain dengan port di log.
Log: "GITHUB_TOKEN belum diisi" / "ditolak GitHub"Isi atau perbarui GITHUB_TOKEN (fine-grained, repo bimbel-infinity-website, Contents: Read and write). Token kedaluwarsa juga menyebabkan ini.
Tool baru tidak munculServer memuat tools saat start. Railway → infinity-konten-mcp → Deployments → Restart.
publish gagal: link rusakPerbaiki link yang disebut di pesan, lalu build_site dan publish lagi.
publish gagal sinkronAda perubahan baru di GitHub dari sumber lain. Ulangi publish; server menarik perubahan terbaru dulu.
ping_index "ditunda"File kunci IndexNow belum tayang. Tunggu deploy 1–2 menit setelah publish, lalu ulangi.
Perubahan belum terlihat di websiteTunggu 1–2 menit (deploy Railway); muat ulang halaman. Kalau tetap, cek apakah publish berhasil (review_changes kosong).

13. Membatalkan perubahan

  1. Buka github.com/anggunn2701-oss/bimbel-infinity-website → Commits.
  2. Cari commit dari "Infinity Konten MCP" yang ingin dibatalkan.
  3. Minta developer menjalankan git revert <commit> lalu push, atau minta asisten mengembalikan isinya dengan tool yang sama (mis. set_theme ke tema sebelumnya, save_post dengan isi lama).
